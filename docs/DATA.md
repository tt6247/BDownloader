# 数据与校验记录

## 目录约定

`AppPaths.RuntimeDirectory` 取正在执行程序集的基目录；`AppPaths.DataDirectory` 取合法的 `BDOWNLOADER_DATA_DIRECTORY` 覆盖值，未配置时回到程序集基目录。读取属性本身不创建目录。

| 数据 | 单文件版默认路径 |
|---|---|
| 运行时缓存 | `%LOCALAPPDATA%/BDownloader/Runtime/<载荷摘要>/payload/` |
| 持久数据根目录 | `%LOCALAPPDATA%/BDownloader/Data/` |
| B站加密会话 | 数据根目录下 `Config/Accounts/bilibili.bin` |
| YouTube 加密会话 | 数据根目录下 `Config/MediaAccounts/youtube.bin` |
| 临时明文 Cookie | `Config/MediaAccounts/session-<进程号>-<随机值>.txt` |
| 队列和设置 | `Storage/media-queue.json` |
| 媒体校验基准 | `Storage/Verification/<路径摘要>.json` |
| 已下载媒体 | 用户选择的输出目录 |

直接运行 `app/BDownloader.exe` 的目录版默认以 `app/` 为数据根目录。目录版与单文件版不会自动迁移账号；首次切换运行方式时可能需要重新登录。

## 队列

`DownloadView.Save` 使用临时文件和原子替换保存输入链接、输出目录、列表标题、模式、画质、完整列表标记及每行状态。条目包含媒体地址、实际路径、校验记录路径、下载模式与高度上限。

重启恢复时，非完成任务变为“等待继续”；标记完成但文件已不存在的任务变为“文件已丢失”。删除队列 JSON 会丢失界面中的下载记录及设置，不会删除视频，也不等同于退出账号。

## v1.0.1 校验记录

下载或重新校验通过后，记录写入应用数据目录，媒体文件旁不再生成 `*.verification.json`。记录内容包括文件名、大小、SHA-256、校验时间、媒体 ID、经过筛选的源地址、期望与实际时长、解码终点、模式、轨道及分辨率。

内部记录文件名按媒体的绝对路径计算：统一路径分隔符、转换为大写，再对 UTF-8 路径做 SHA-256。不同目录中的同名视频因此拥有独立记录。重新校验根据当前文件路径查找，重命名或移动媒体后不会自动找到原路径对应的内部基准；此时仍可完整解码并建立新记录，但不能据此证明移动前后的字节一致。

旧版记录处理顺序：

1. 重新校验优先读取内部记录；没有内部记录时读取媒体旁的旧 `*.verification.json`。
2. 完成轨道、时长、全解码与摘要检查，并与已有基准比对。
3. 成功写入内部记录后，删除该媒体对应的旧校验 JSON，再报告成功。

失败或取消时，重新校验保留原基准；不会批量扫描并删除其他 JSON。若旧文件删除因权限或占用失败，本次操作会报告失败，不会在未清理成功时声称完成。重新下载属于获取新媒体的流程，可以更新旧的内部基准。

用户可以删除内部校验记录，播放不受影响，但下次校验无法对照原始下载时的 SHA-256。发行附件 `BDownloader.exe.manifest.json` 是另一种文件：它描述程序和内置工具，用于发行审计，与视频校验记录无关；单文件启动器还包含自己的内嵌校验清单。

## 会话与测试隔离

持久会话使用 `DataProtectionScope.CurrentUser`，复制加密文件到其他 Windows 账号不保证可用。YouTube 导入时筛选域名与过期条目；调用下载工具前才创建带当前用户访问限制的明文临时 Cookie，结束后释放删除，并清理已退出进程的遗留文件。仍在使用的其他会话不会因清理被删除。

测试可以设置 `BDOWNLOADER_DATA_DIRECTORY`。单文件启动器还支持 `BDOWNLOADER_CACHE_DIRECTORY`，两者必须是独立、不重叠的完整本地磁盘路径；启动器拒绝运行缓存路径中的符号链接或目录联接。`BDOWNLOADER_RUNTIME_DIRECTORY` 由启动器传给子进程，但应用的运行目录仍以程序集基目录为准。

账号、Cookie、队列、媒体、日志与本机校验报告不应进入 Git。使用测试脚本生成的独立沙箱进行验证，不复制用户的真实登录数据。
